# New-user home skeleton

`install` copies `home/` into `/etc/skel` without deleting distribution or
administrator files. Both host Plasma/Wayland accounts and VM XFCE/Xorg
accounts use the same skeleton. Desktop-specific files are harmless outside
their desktop, and XFCE/VM autostarts declare `OnlyShowIn=XFCE`.

The payload contains deliberate user preferences, including the repository's
Git identity. It does not contain caches, clipboard history, Plasma activity
databases, display topology, libvirt state, session state, or other files
generated by a graphical login.

Distribution branding is not copied here. Plasma obtains openSUSE branding
from system KConfig defaults in `/etc/xdg` and themes under `/usr/share/plasma`.
The administrator skeleton deliberately overrides only Plasma's color and icon
preferences: `Sweet-dark` and `Sweet-Purple`, matching XFCE. Those assets are
provided by this repository under `/usr/local/share` after provisioning. KDE's
global KConfig path references that same standalone color-scheme file, so its
palette is not duplicated in each user's `kdeglobals`.
Konsole discovers the repository's separate `dark` and `white` profiles from
the system data directory. The skeleton installs user-owned copies under
`.local/share/konsole`, so they remain editable, and selects `dark.profile` by
default. Both profiles use JetBrains Mono 10 and Konsole's ASCII word mode for
programming ligatures. The same font is the KDE fixed-width default, the
Kate/KWrite editor default, and the system fontconfig `monospace` preference.
The user-local openSUSE Plasma layout template supplies a top, non-floating
32-pixel panel with the regular icon-and-text task manager, Dolphin and Konsole
launchers, the configured date/time format, and the standard pager, tray, and
show-desktop widgets. It intentionally replaces only the distribution's panel
template; Plasma still generates account, activity, display, and containment
state on first login.
The skeleton does not force `GTK_THEME`, so GTK applications in Plasma retain
the distribution's KDE/GTK integration. XFCE obtains packaged themes, icons,
backdrops, and desktop data under `/usr/share`; its per-user panel, power, and
appearance choices in this skeleton intentionally override `/etc/xdg/xfce4`.
The skeleton does not contain per-monitor XFCE or Plasma wallpaper state. VM
provisioning installs `vm-cleanup.service`, which removes packaged wallpapers
and backdrops during setup and on every boot. This keeps wallpaper policy
VM-specific while allowing a Plasma host to retain its configured wallpaper.

On openSUSE Tumbleweed, `useradd` combines vendor files from `/usr/etc/skel`
with administrator overrides in `/etc/skel`. On Ubuntu, `/etc/skel` itself
contains the vendor seed. The installer intentionally does not use `--delete`,
so unmanaged paths survive; managed same-path files are deliberately replaced.
